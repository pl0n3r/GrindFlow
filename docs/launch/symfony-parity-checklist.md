## Método de comparación sin producción

1. **Fixture `PROPUESTA`:** crear organizaciones ficticias A/B, membresías y recursos falsos independientes; no reutilizar identificadores, secretos o sesiones de producción.
2. Para cada GF-*, comparar por separado autorización, lectura, mutación, rechazo cross-tenant, estados HTTP o salidas de jobs según corresponda. Donde la ruta sea `UNKNOWN`, documentar qué superficie deberá encontrar el operador antes de comparar.
3. Usar únicamente pruebas y rutas de código de [GF-MIG-003](../PARITY-MATRIX-EXECUTABLE.md) como **referencias**, nunca como recibo de equivalencia funcional. Incluir negativos de IDOR, denegación de permisos, duplicados, idempotencia, errores controlados y cero fuga entre tenants cuando aplique.
4. Registrar resultado por requisito y tenant con hash de fixture sintético, SHA de ambos candidatos, fecha, ejecutor y evidencia de prueba **solo cuando exista ejecución auténtica**. Hasta entonces: `NO ENSAYADO` y `PENDIENTE`.
5. Prueba del documento: `python3 -m unittest discover -s tests -p test_paridad_symfony_doc.py -v` (revisión estática). **No sustituye** la aceptación, CI ni el smoke del runtime.
